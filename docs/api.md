# MOA API 명세 초안 (화면 기준)

> 2026-10-12 초안에 "8. 정한 것과 정할 것"의 결정을 반영함.

이 문서는 **화면이 서버에 무엇을 보내고 무엇을 받아야 하는지**를 화면 코드(`frontend/`) 기준으로 정리한 것이다. 서버 안에서 어떤 모델을 어떻게 돌릴지는 각 담당자가 정한다. `(미정)` 표시는 담당자와 정해야 하는 부분이다.

## 0. 읽는 법

- **주소**: 화면이 요청을 보내는 서버 주소. 모두 `/api`로 시작한다.
- **방식**: `GET`은 가져오기, `POST`는 새로 만들기, `PATCH`는 일부 고치기, `DELETE`는 지우기.
- **보내는 값 / 받는 값**: 특별히 적지 않으면 JSON(이름과 값을 짝지은 글자 형식)이다. 사진을 보낼 때는 파일 첨부(`multipart/form-data`)로 보낸다.
- **로그인 필요**: 로그인할 때 받은 토큰(로그인 증표 글자)을 요청 머리에 `Authorization: Bearer <토큰>`으로 넣는다.
- **오류**: 실패하면 상태 번호(400, 401, 404, 500 등)와 함께 아래 형식으로 돌려준다. 화면은 `message`를 그대로 안내 문구로 띄운다.

```json
{ "error": { "code": "INVALID_IMAGE", "message": "이미지를 읽을 수 없습니다." } }
```

상태 번호 뜻 (이 서버에서 쓰는 것)

| 번호 | 뜻 | 예 |
|---|---|---|
| 400 | 보낸 값이 잘못됨 | 사진 형식 틀림, 비밀번호 규칙 어김, 필수 값 빠짐 |
| 401 | 로그인 필요 (토큰 없음·틀림·만료) 또는 로그인 실패 | `UNAUTHORIZED` → 화면은 로그인 창, `INVALID_CREDENTIALS` → 아이디·비밀번호 틀림 |
| 404 | 없음 (남의 사진·결과도 없는 것처럼 404) | `RESULT_NOT_FOUND`, `IMAGE_NOT_FOUND` |
| 409 | 이미 있음 | `DUPLICATE_USERNAME` (아이디 중복) |
| 503 | 서버가 지금 쓸 수 없음 | `DB_UNAVAILABLE` (MySQL 연결 안 됨) |
| 500 | 서버 안의 예상 못 한 오류 | |

## 1. 화면 흐름과 API 대응

| 화면 | 사용자가 하는 일 | 쓰는 API |
|---|---|---|
| 로그인 팝업 | 아이디, 비밀번호 입력 | 2-1 로그인 |
| 회원가입 버튼 | (지금은 "준비 중") | 2-2 회원가입 |
| 합성하기 1단계 | 상의 사진 고르기 (예시 또는 업로드) | 3-1 사진 올리기 |
| 합성하기 2단계 | 인물 사진 고르기 (예시 또는 업로드) | 3-1 사진 올리기 |
| 합성하기 3단계 | 상의 위에 점 찍기 (왼쪽 클릭 포함, 오른쪽 클릭 제외) → 확인 | 4-1 상의 추출 |
| 합성하기 4단계 | 인물 사진에 입힐 영역 칠하기 (점, 브러시, 지우개) → 확인 | 5-1 합성 요청 |
| 합성 중 화면 | 기다리기 | 5-2 진행 확인 |
| 결과 화면 | 결과 보기, 저장하기 | 5-3 결과 받기, 6-2 저장/좋아요 |
| 오른쪽 "내 작업 기록" | 저장한 결과 다시 보기 | 6-1 결과 목록 |
| 마이페이지 사진첩 | 전체 / 최근 작업 / 좋아요 탭, 날짜 거르기, 정렬, 저장, 좋아요 | 6-1 결과 목록, 6-2 저장/좋아요 |
| 마이페이지 프로필 | 이름, 이메일, 사진 보기 | 2-3 내 정보 |

## 2. 계정

### 2-1. 로그인
`POST /api/auth/login`, 로그인 필요 없음

보내는 값
```json
{ "username": "test", "password": "test" }
```
받는 값
```json
{ "token": "로그인 증표 글자", "user": { "id": 1, "username": "test", "name": "MOA User" } }
```
- 틀리면 401, `message`: "아이디 또는 비밀번호가 올바르지 않습니다".
- 로그아웃: 화면이 토큰을 지우고 서버에도 알린다 → 2-4.

### 2-2. 회원가입
`POST /api/auth/register`, 로그인 필요 없음

보내는 값: `{ "username", "password", "name", "email" }`
받는 값: 로그인과 같음 (가입 후 바로 로그인 상태)
- 아이디 중복이면 409, `code`: `DUPLICATE_USERNAME`.
- 비밀번호 규칙: **8자 이상, 숫자 1개 이상 포함**. 어기면 400, `code`: `INVALID_PASSWORD`, `message`: "비밀번호는 8자 이상이고 숫자를 포함해야 합니다". 화면도 보내기 전에 같은 규칙으로 먼저 검사하고 같은 안내를 보여 준다.

### 2-3. 내 정보
`GET /api/me`, 로그인 필요

받는 값
```json
{ "id": 1, "username": "test", "name": "MOA User", "email": "moa.user@example.com", "avatar_url": "/api/files/..." }
```

### 2-4. 로그아웃
`POST /api/auth/logout`, 로그인 필요

보내는 값: 없음. 받는 값: `{}`
- 서버는 이 토큰을 더 이상 받지 않게 처리한다.
- 화면은 응답을 기다리지 않고 바로 로그아웃 상태가 된다. 이미 만료된 토큰이라 401이 와도 무시한다.

## 3. 사진

### 3-1. 사진 올리기
`POST /api/images`, 로그인 필요, 파일 첨부

보내는 값: `file` (jpg, png), `kind`: `"garment"`(상의 사진) 또는 `"person"`(인물 사진)
받는 값
```json
{ "image_id": "img_123", "url": "/api/files/img_123.jpg", "width": 768, "height": 1024 }
```
- 화면은 1, 2단계에서 "이 사진으로 선택"을 누를 때 올린다. 예시 사진을 골라도 똑같이 올린다.
- 이후 추출과 합성은 사진 파일 대신 `image_id`로 요청한다 (같은 사진을 여러 번 보내지 않으려고).
- 크기 제한: **10MB 이하**, jpg/png만. 넘으면 400, `code`: `IMAGE_TOO_LARGE` 또는 `INVALID_IMAGE`. 화면도 올리기 전에 먼저 검사한다.
- 긴 변 길이 제한 (미정, 제안: 4096 이하).

## 4. 상의 추출 (3단계)

### 4-1. 상의 추출
`POST /api/extract`, 로그인 필요

보내는 값
```json
{
  "image_id": "img_123",
  "points": [
    { "x": 0.52, "y": 0.41, "label": 1 },
    { "x": 0.70, "y": 0.20, "label": 0 }
  ]
}
```
- `x`, `y`: 사진 안에서의 위치를 **0~1 비율**로 (왼쪽 위 0,0 / 오른쪽 아래 1,1). 화면에 보이는 크기와 원본 크기가 달라서 비율로 보낸다.
- `label`: 1은 포함(왼쪽 클릭), 0은 제외(오른쪽 클릭).

받는 값
```json
{
  "extraction_id": "ext_456",
  "mask_url": "/api/files/ext_456_mask.png",
  "cutout_url": "/api/files/ext_456_cutout.png",
  "bbox": { "x": 120, "y": 200, "w": 400, "h": 520 }
}
```
- `mask_url`: 원본 사진과 같은 크기의 흑백 PNG (상의 255, 나머지 0). 화면은 이걸 사진 위에 반투명 색으로 겹쳐 보여 준다.
- `cutout_url`: 상의만 남기고 배경을 투명하게 한 PNG. 왼쪽 "추출된 객체" 칸에 쓴다.
- `bbox`: 상의를 감싸는 사각형 (원본 픽셀 기준).
- **확인을 누를 때 한 번만 부른다.** 점을 찍는 동안에는 서버에 묻지 않는다.
- 화면 흐름 (UI 담당):
  1. 점을 다 찍고 확인을 누르면 4-1을 부른다.
  2. 받은 `mask_url`을 사진 위에 겹쳐 보여 주고 **"이대로 진행" / "점 다시 찍기"** 중에서 고르게 한다.
  3. 다시 찍고 확인하면 4-1을 또 부른다 (새 `extraction_id`를 받는다). "이대로 진행"을 누른 결과의 `extraction_id`를 5-1에 쓴다.

## 5. 합성 (4단계)

합성은 시간이 걸려서 **요청하면 작업 번호를 바로 받고, 끝났는지 주기적으로 확인한 뒤 결과를 받는** 방식으로 한다.

- 합성 설정: **50스텝**, 한 번 합성에 **1분 안팎**을 목표로 한다. (참고: 2026-10-12 기준 RTX 3080에서 AnyDoor 50스텝이 약 6분 반 걸릴 것으로 추정되어, 목표를 맞추려면 서버 쪽 최적화가 필요하다.)

### 5-1. 합성 요청
`POST /api/compose`, 로그인 필요, 파일 첨부

보내는 값
- `extraction_id`: 4-1에서 받은 번호 (어떤 상의를 입힐지)
- `person_image_id`: 3-1에서 받은 인물 사진 번호
- `area_mask`: 입힐 영역 흑백 PNG (칠한 곳 255, 나머지 0). 인물 사진과 같은 비율이면 되고, 크기는 서버가 원본에 맞춘다.

받는 값
```json
{ "job_id": "job_789", "status": "queued", "queue_position": 1 }
```
- 합성 설정(스텝 수, 시드 등)은 화면에서 고르지 않는다. 스텝은 50, 시드 등 나머지는 서버 담당자가 정한다.

### 5-2. 진행 확인
`GET /api/jobs/{job_id}`, 로그인 필요

받는 값
```json
{ "job_id": "job_789", "status": "running", "progress": 0.34, "queue_position": 0, "result_id": null, "error": null }
```
- `status`: `queued`(대기) / `running`(합성 중) / `done`(완료) / `failed`(실패)
- `progress`: 0~1 진행률 (예: 50스텝 중 17스텝이면 0.34). 화면의 "합성중" 표시에 쓴다. 못 주면 `null`.
- 화면은 **2초마다** 부른다. `done`이면 `result_id`로 5-3을 부른다.
- 합성 중에 새로고침하거나 다른 화면으로 가도 이어서 확인할 수 있게, 화면은 `job_id`를 브라우저에 저장해 둔다.

### 5-3. 결과 받기
`GET /api/results/{result_id}`, 로그인 필요

받는 값
```json
{
  "result_id": "res_001",
  "image_url": "/api/files/res_001.png",
  "thumb_url": "/api/files/res_001_thumb.jpg",
  "created_at": "2026-10-12T20:45:00+09:00",
  "saved": false,
  "favorite": false,
  "garment_image_id": "img_123",
  "person_image_id": "img_124"
}
```
- 합성이 끝나면 결과는 자동으로 "최근 작업"(`saved: false`)으로 남는다. 사용자가 "저장하기"를 누르면 사진첩(`saved: true`)으로 옮긴다.
- 저장하지 않은 결과는 만든 지 **3일** 뒤 서버가 지운다. 화면은 "최근 작업" 탭에 "저장하지 않은 결과는 3일 뒤 사라집니다" 같은 안내를 보여 준다.

## 6. 작업 기록과 사진첩

### 6-1. 결과 목록
`GET /api/results`, 로그인 필요

주소 뒤에 붙이는 조건 (모두 선택)
- `saved=true|false`: 사진첩 "전체"는 `true`, "최근 작업"은 `false`
- `favorite=true`: "좋아요" 탭
- `date=2026-10-12`: 그날 만든 것만. **한국 시간(+09:00) 기준**의 하루다.
- `sort=new|old`: 최신순 / 오래된순 (기본 `new`)
- `limit`, `cursor`: 많을 때 나눠 받기 (미정)

받는 값
```json
{
  "items": [ { "result_id": "res_001", "thumb_url": "...", "image_url": "...", "created_at": "...", "saved": true, "favorite": true } ],
  "counts": { "saved": 20, "recent": 6, "favorite": 6 },
  "next_cursor": null
}
```
- `counts`: 탭 옆 숫자 (전체, 최근 작업, 좋아요)
- 합성하기 화면 오른쪽 "내 작업 기록"은 `saved=true`, 최신순으로 쓴다.

### 6-2. 저장 / 좋아요
`PATCH /api/results/{result_id}`, 로그인 필요

보내는 값: 바꿀 것만 `{ "saved": true }` 또는 `{ "favorite": true }`
받는 값: 5-3과 같은 결과 정보

### 6-3. 결과 지우기 (미정)
`DELETE /api/results/{result_id}`. 지금 화면에는 지우기 버튼이 없다.

## 7. 파일

`GET /api/files/{파일 이름}`: 위 응답의 `url`들. 로그인한 본인 것만 볼 수 있어야 한다.

- 화면은 받은 주소를 `<img src="...">`에 그대로 넣는다. 이렇게 브라우저가 직접 가져가는 요청에는 `Authorization` 머리를 붙일 수 없다. 그래서 토큰 머리로만 확인하면 사진이 모두 막힌다.
- 확인 방식 (미정, **서버가 이 주소를 만들기 전까지 결정**). 후보:
  - (가) 서버가 일정 시간만 열리는 주소를 준다. 예: `/api/files/res_001.png?key=...` (제안)
  - (나) 로그인을 쿠키로 한다
  - (다) 화면이 토큰을 붙여 직접 받아서 보여 준다 (사진이 많으면 느림)

### 정할 것

1. 사진 주소(`/api/files`)의 본인 확인 방식. 서버가 이 주소를 만들기 전까지 (7장)
2. 사진 긴 변 길이 제한 (3-1)
3. 결과 목록 나눠 받기(`limit`, `cursor`) (6-1)
4. 결과 지우기 (6-3)
