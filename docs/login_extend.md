# 로그인 시간 연장 (화면 담당 전달용)

- 정한 날: 2026-10-15 (서버 담당 제안, 팀 합의 필요). 명세 외 추가
- 서버 준비 완료, 화면 요청 함수 준비 완료 → **화면에 안내 창만 붙이면 됨**

## 1. 기본 규칙

- 로그인 유효 시간: **로그인한 시각부터 3시간** (날짜·자정 기준 아님)
- 서비스를 쓰고 있어도 저절로 늘어나지 않음 → 만료 전에 사용자에게 연장 여부를 물음
- 연장하면: **연장한 시각부터 다시 3시간**
- 연장 횟수 제한 없음

## 2. 안내 창 띄우는 때

| 때 | 안내 | 버튼 |
|---|---|---|
| 만료 **30분 전** (1차) | "30분 뒤 자동 로그아웃됩니다. 로그인 시간을 연장할까요?" | [연장] [아니요] |
| 만료 **10분 전** (재확인) | "10분 뒤 자동 로그아웃됩니다. 로그인 시간을 연장할까요?" | [연장] [아니요] |
| 만료 시각 | 로그아웃 처리 + 로그인 창 | - |

- 1차에서 [연장] → 재확인 띄우지 않음. 새 만료 시각 기준으로 다시 30분 전부터 같은 순서
- 1차에서 [아니요]·창 닫기·응답 없음 → 10분 전에 재확인
- 재확인에서도 [아니요]·응답 없음 → 만료 시각에 로그아웃
- 안내 문구는 예시. 화면 담당이 자유롭게 정함

```
로그인 3:00 ─── 5:30 1차 확인
                  ├─ [연장] → 만료 8:30 → 8:00에 다시 1차 확인
                  └─ [아니요]/무시 ─── 5:50 재확인
                                        ├─ [연장] → 만료 8:50
                                        └─ [아니요]/무시 → 6:00 로그아웃
```

## 3. 쓰는 함수 (`frontend/src/api/auth.js`, 준비됨)

| 함수 | 하는 일 |
|---|---|
| `getExpiresAt()` | 만료 시각(`Date`). 로그인 안 했으면 `null`. 타이머 기준 |
| `extendLogin()` | 서버에 연장 요청 → 새 만료 시각(`Date`) 반환. 저장도 자동 |
| `login()`, `logout()` | 기존 그대로. 만료 시각 저장·삭제를 함께 처리 |

- 만료 시각은 브라우저 저장소(`localStorage`)에 있음 → 새로고침해도 유지
- 이미 만료된 뒤 `extendLogin()`을 부르면 서버가 401 → 기존 처리대로 로그아웃 + 로그인 창 (`moa:unauthorized`)
- 가짜 서버(`mock`)에서도 같은 응답이 오므로 서버 없이 화면 작업 가능 (가짜 서버는 만료를 실제로 확인하지는 않음)

## 4. 서버 주소 (참고)

- 로그인·회원가입 응답에 `expires_at` 추가
  ```json
  { "token": "...", "expires_at": "2026-10-15T18:20:00+09:00", "user": { "id": 1, "username": "test", "name": "MOA User" } }
  ```
- `POST /api/auth/extend`, 로그인 필요, 보내는 값 없음
  - 받는 값: `{ "expires_at": "2026-10-15T21:05:00+09:00" }`
  - 토큰 글자는 그대로, 만료 시각만 늘어남
  - 이미 만료된 토큰: 401 `UNAUTHORIZED` (다시 로그인)
- 시각은 한국 시간(+09:00)
