  - AnyDoor 공식 학습과 같은 한 번에 32장이라 학습률 1e-5 를 그대로 씀
  - GPU 메모리 약 36% 사용

### 4-3. 본 학습 설정

| 항목 | 1안 | 2안 |
|---|---|---|

| 배치 / 스텝 | 32 / 10,000 | 32 / 10,000 |
| 학습률 | 1e-5 고정 | 1e-5 고정 |
| 저장 | 1,000스텝마다 (10개, 1개 약 9.8GB) | 같음 |

- 사전 시험의 1,000스텝(배치 1)은 학습용 컴퓨터 GPU 한계에 맞춘 값이라 이번에 늘림
  - 스텝을 늘리면 결과가 좋아질 것 (추정)
- 1에폭 = 10,988쌍 ÷ 32 = 344스텝 (올림)
- 학습률이 고정(AdamW, 스케줄러 없음)이라 중간 저장 가중치는 그 스텝까지만 따로 학습한 것과 같은 과정
  - 1k·5k·10k 를 따로 세 번 학습하지 않고 한 번 학습으로 얻음
  - 다른 점은 사진 순서뿐
- 저장 용량: 1안·2안 합계 약 196GB (여유 4.3TB)
- 실행 방식: 터미널과 분리해 실행, 접속이 끊겨도 계속
- 시작 약 5분 뒤 확인: 스텝당 1.1초, GPU 최대 64.4GB, GPU 사용률 72%
  - 배치 측정과 같은 속도

### 4-4. 학습 길이와 과적합

| 학습 길이 | 스텝 | 학습 시간 (추정) | 저장 용량 (추정) |
|---|---|---|---|

| 80에폭 | 27,520 | 약 8시간 43분 | 265GB |
| 100에폭 | 34,400 | 약 10시간 54분 | 333GB |

- 학습 시간: 스텝당 1.14초 기준
  - 실제 1안은 10,000스텝에 3시간 30분으로 이 계산보다 약 20분 김
  - 다른 길이도 저장 등의 시간만큼 더 걸릴 수 있음 (추정)
- 저장 용량: 1,000스텝마다 저장 기준
- 과적합 여부는 측정 근거 없음
  - 이 프로젝트에서 가장 긴 학습은 1,000장 (약 0.1에폭)
  - 직접 재야 알 수 있음
- 과적합을 줄이는 요소
  - 크롭 배율 1.3–1.9 무작위
  - 잡음 세기 1,000단계 무작위
  - 낮은 학습률 1e-5
  - 2.5B 중 1.2B 만 학습
  - 1안은 밝기·대비 증강
- 걱정되는 것 (추정)
  - 같은 10,988쌍 반복으로 VITON-HD(흰 배경·정면) 쪽에 치우침
  - 색 바뀜 증가
  - VITON-HD 시험 사진은 좋아 보여도 앱 사진(실제 배경·다양한 자세)은 나빠질 수 있음
- 확인 방법
  - 저장 가중치별 유형 B 비교 (5장 × seed 3, 95장)
  - 검증 손실 (4-5)
  - VITON-HD 가 아닌 사진으로 합성 비교 (쉐이프리스 평가 30쌍, 학습용 컴퓨터에 준비됨)
- 10,000스텝 이후 추가 학습 여부는 1k·5k·10k 비교 결과로 결정
- 더 학습할 때는 10k 가중치에서 이어서 학습 (`--resume`)
  - 저장 가중치에 옵티마이저 상태가 없어 이어 학습 초반은 계속 학습한 것과 조금 다를 수 있음 (추정)

### 4-5. 검증 손실 (작성, 서버 실행 전)

- 필요한 이유: 팀 학습 코드는 학습 손실만 출력해 과적합을 판단할 수 없음
- 스크립트: `Dataset\retrain_run\기록\tools\val_loss.py`
  - 팀 학습 코드·AnyDoor 코드는 불러 쓰기만 하고 수정하지 않음
- 계산식: 학습 중 출력되는 손실과 같음
  - 예측한 잡음과 넣은 잡음의 평균 제곱 오차 (AnyDoor `p_losses`)
  - 시작할 때 설정값을 검사해 식이 다르면 멈춤
- 학습 중 손실과 다른 점: 무작위 값을 고정해 모든 가중치가 같은 문제를 풂

| 항목 | 값 |
|---|---|
| 검증 사진 | VITON-HD test (학습에 안 쓴 사진) 512장 |
| 학습 사진 | 학습 쌍 목록에서 512장 (검증 손실과의 차이 확인용) |
| 학습 재료 | 팀 학습 재료 생성 코드, 밝기·대비 증강 끔 (1안·2안 같은 조건) |
| 잡음 세기 | 사진마다 4개 (0–999 를 4구간으로 나눠 구간마다 1개) |
| 고정하는 값 | 사진 선택, 크롭 배율, 잡음 세기, 잡음 |
| 비교 기준 | AnyDoor 공식 가중치 |

- 결과: `/NHNHOME/workspace/val_loss/val_loss.csv` (가중치 1개 = 1줄)
  - 검증 손실, 공식 가중치 대비 차이와 표준오차, 학습 사진 손실, 검증 − 학습 차이
- 해석 기준
  - 공식 대비 차이가 표준오차의 2배보다 작으면 차이 없음
  - 검증 손실이 줄다가 늘거나 검증 − 학습 차이가 커지면 과적합 신호
  - 손실은 그림 품질을 직접 재지 않으므로 유형 B 비교와 함께 판단
- 확인 상태: 문법 검사만 통과, 서버 동작 미확인
- 실행 방법: 실행 절차 13단계
