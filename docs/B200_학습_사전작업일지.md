## 용어 설명

### 쌍 (학습 쌍)
- 쌍 1개 = 옷 사진 1장 + 그 옷을 실제로 입은 사람 사진 1장 + 딸린 정보 파일. 모델이 "이 옷을 이 사람에게 입히면 이렇게 보인다"를 배우는 문제 1개
- VITON-HD 쌍 1개 (예: `00000_00`) = 파일 6개

| 파일 | 내용 |
|---|---|
| `cloth/00000_00.jpg` | 옷만 찍은 제품 사진 |
| `cloth-mask/00000_00.jpg` | 제품 사진의 옷 영역 |
| `image/00000_00.jpg` | 그 옷을 입은 사람 사진 (정답) |
| `image-parse-v3/00000_00.png` | 사람 사진 부위 지도 (5번 = 상의) |
| `agnostic-mask/00000_00_mask.png` | 상체 + 팔 영역 (다시 그릴 자리) |
| `openpose_json/00000_00_keypoints.json` | 관절 점 (목·어깨·골반 등) |

- 쉐이프리스 쌍: `Pair.json` 의 제품 사진 → 착용 사진 (예: `KSOT0400M000P00A1` 가디건 제품 정면 → `KSOT0400M332P11A1` 모델 332·포즈 11·정면 착용)
- 쌍 수: VITON-HD 학습용 11,647 → 팀 거르기 통과 10,988, 팀 시험·10/26 학습 100 (짧은 상의 50 + 무작위 50), 쉐이프리스 28,084 (상의류 22,780)

### 스텝 (학습 스텝)
- 스텝 1번 = 모델을 한 번 고치는 단위: ① 쌍에서 학습 재료(옷 사진 224, 정답 크롭 512, 옷 자리를 비운 조건 이미지 512)를 배치 크기만큼 만듦 → ② 정답에 무작위 세기 잡음을 섞고 모델이 잡음을 얼마나 맞히는지 봄 (틀린 정도 = 손실) → ③ 틀린 만큼 학습 부분(ControlNet, UNet 뒷부분)을 조금 고침
- 배치 = 한 스텝에 보는 장수 (배치 1 = 1장, 배치 32 = 32장을 보고 한 번 고침)
- 에폭 = 전체 쌍을 한 번씩 다 보는 것

| 학습 | 스텝 | 배치 | 본 장수 | 반복 | 걸린 시간 |
|---|---|---|---|---|---|
| 7장 2 동작 확인 (10/26) | 20 | 1 | 20장 | 100쌍 중 일부 | 536초 |
| 짧은 학습 (10/26) | 400 | 1 | 400장 | 100쌍 × 약 4번 (4에폭) | 1시간 50분 |
| 팀 시험 (재학습 시험 PC) | 1,000 | 1 | 1,000장 | 100쌍 × 약 10번 | 약 6시간 |
| 팀 README B200 예시 | 10,000 | 32 (GPU 8 × 4) | 32만 장 | 10,988쌍 × 약 29번 | 미측정 |

- 다른 것: 합성(결과 확인)의 "50스텝" = 이미지 1장을 만들 때 잡음을 50번에 나눠 걷어 내는 단계 수, 모델을 고치지 않음 (1장 약 22초)
- 스텝 수에 따른 차이: 스텝이 늘면 모델을 고치는 횟수와 본 사진 수가 늘어남. 반복 횟수는 배치·쌍 수와 함께 정해짐 (예: 학습용 컴퓨터 배치 1·100쌍·10,000스텝 = 100쌍 × 100번, 약 44시간, 계산)
  - 확인: 400스텝 = 유형 B 엉뚱한 천 15 → 1장, V28 옷 길어짐·손 천 조각 남음. 1,000스텝 (재학습 시험 PC) = 유형 B 15장 모두 깨끗, 95장 좋아짐 20·나빠짐 6
  - 추정: 늘리면 재학습 방식 입력을 더 확실히 익히고 네모 어두워짐이 줄 수 있음. 너무 반복하면 VITON-HD(단색 배경·정면)에 치우치거나 공식 가중치가 이미 가진 능력이 약해질 수 있음
  - 중간 저장(예: 2,000스텝마다) 후 95장 비교로 가장 좋은 지점을 고르는 방식 권장 (팀 README 와 같음)
- 과적합: 학습한 사진에는 잘 맞고 처음 보는 사진에서는 나빠지는 현상, 반복이 많고 데이터가 단조로울수록 생기기 쉬움
  - 확인: 100쌍 × 약 4~10번 학습에서도 학습 쌍과 겹치지 않는 VITON-HD 시험용 사진에서 유형 B 개선 → VITON-HD 안에서는 효과 있음. 95장 비교의 색 바뀜·없던 물건이 과적합 때문인지는 미확인
  - 팀 학습 스크립트는 학습 손실만 출력, 따로 떼어 둔 사진의 검증 손실 없음 (코드 확인) → 손실로는 과적합 판단 불가
  - 우려 (추정): VITON-HD(단색 배경·정면)에 치우침, 앱 사진(실제 배경·다양한 자세)은 미시험, 큰 배치에서 스텝을 그대로 두면 반복 급증
  - 대응: 중간 저장 + 처음 보는 평가 세트(95장, 쉐이프리스 평가 30쌍, 색 있는 배경 사진)로 비교, 데이터 다양화(쉐이프리스·FashionTryOn·일반 데이터, 추천 3·4안), 배치를 키우면 스텝 줄이기
- 학습 스텝 수는 합성 속도와 관계없음: 학습은 숫자 값만 바꾸고 개수·구조는 그대로 (가중치 파일 항상 9.8GB). 측정: 같은 15장 합성 1장당 공식 가중치 23.0초, 400스텝 가중치 21.3초. 합성 속도를 바꾸는 것은 DDIM 스텝 수, 그림 크기, GPU, 합성 설정(부품 나눠 올리기)

### 증강 (밝기·대비 증강, `ref_aug`)
- 학습 재료를 만들 때마다 참조 이미지(옷 사진 224)의 밝기·대비를 무작위로 바꾸는 것. 같은 쌍도 볼 때마다 조금씩 다른 옷 사진이 됨 (`scripts/retrain/retrain_dataset.py`, 코드 확인)
  - 설정: `RandomBrightnessContrast(p=0.5)` = 절반 확률로 적용, 밝기·대비 각각 최대 ±20% (albumentations 1.3.0 기본값, 확인). AnyDoor 공식 학습 코드와 같은 설정에서 좌우 뒤집기만 뺌
  - 같은 변경을 조건 이미지에 놓는 옷 그림에도 적용, 정답(착용 사진)은 바꾸지 않음 (코드 확인)
  - 팀 기본값은 켜짐, `--no-ref-aug` 로 끔 → 추천 2안 "증강 끄기" = 이 옵션만 끈 학습 (나머지는 1안과 같음)
- 끄고 비교하는 이유: 재학습 시험 PC 10/25 1,000스텝 학습(증강 켬, 입고 있던 상의 영역 포함)에서 95장 중 색 바뀜 5장. 원인 미확인 (증강 / 입고 있던 상의 영역 포함 / 학습마다 생기는 우연한 차이)
  - 추정: 옷 사진 밝기는 바뀌는데 정답 색은 그대로라, 옷 사진 색과 결과 색이 조금 달라도 된다고 배울 수 있음 → 1안(켬)과 2안(끔)을 같은 스텝으로 학습해 95장의 옷 색 비교
- 다른 것: "보정" = 3안의 쉐이프리스 옷 그림 크기·위치 상수 맞추기 (10/26 ③), 증강과 무관

  - 빨라질 이유: RTX 3080 에서는 GPU 메모리 22.4GB 중 14.3GB 를 공유 GPU 메모리(RAM)로 사용 (확인) → B200 은 메모리가 커서 RAM 을 쓰지 않고 계산도 빠름 (공개 정보 기준, 추정). 몇 배인지는 README 7장 2 의 20스텝 확인으로 측정
  - 걸림돌 후보: 팀 학습 스크립트는 Windows 에서 학습 재료 작업자 수 기본 0 (`retrain_train.py --workers`, 확인) → CPU(4코어)가 재료를 만드는 동안 GPU 대기, 배치를 키우면 더 커질 수 있음 (추정). 배치 1 그대로면 B200 을 다 쓰지 못함
  - 제안 (실행 안 함): 학습 재료 1장 만드는 시간을 CPU 로 미리 측정 (몇 분)
- B200 스텝·배치
  - 1,000스텝·배치 1 은 학습용 컴퓨터(RTX 3080) 한계와 재학습 시험 PC 시험 비교용 값. 팀 README B200 예시 = 10,000스텝, GPU 8개 × 배치 4 (한 번에 32장, AnyDoor 공식 학습과 같음, 확인)
  - 배치 1 의 22.4GB 는 대부분 고정 메모리(가중치·학습용 값)로 보임 → B200 에서는 배치 여유 큼 (추정), README 대로 20스텝씩 배치를 올려 가며 한도 측정
  - 스텝을 늘리면 반복 횟수 증가: VITON-HD 10,988쌍, 배치 32 × 10,000스텝 = 약 29번 반복 → 중간 저장(2,000스텝마다) 후 95장 비교로 가장 좋은 지점 고르기 권장
  - CPU 4코어가 큰 배치의 학습 재료를 따라오는지 확인 필요 (추정, 미측정), 1~4안 비교 시 스텝·배치는 네 안 모두 같게
  - 제안 순서: B200 장착 → 배치별 20스텝 확인 (메모리·스텝 시간) → 반복 횟수 결정 → 스텝 수·저장 간격 결정
  - 배치 256 후보, 확인할 것 3가지
    - 메모리: 장당 추가 메모리 미측정, 장당 0.3~1GB 라면 256장에 77~256GB 추가 (추정) → B200 메모리(공개 정보 기준 약 180~192GB) 안에 드는지 배치 8 → 32 → 64 → 128 → 256 으로 20스텝씩 확인
    - 반복: VITON-HD 10,988쌍이면 배치 256 은 43스텝에 전체 1번, 10,000스텝이면 약 233번 → 스텝 수를 크게 줄여야 함 (계산). AnyDoor 공식 학습은 32장·학습률 1e-5, 배치를 키울 때 학습률 조정 필요 여부는 이 프로젝트에서 미확인
    - CPU: 스텝마다 학습 재료 256장을 4코어 CPU 가 만듦, 1장 0.2초라도 스텝당 약 50초 (추정) → 학습 재료 1장 시간 측정이 핵심
    - RAM (위 메모리는 B200 GPU 메모리 기준, RAM 은 따로)
      - 학습용 컴퓨터 RAM 31.7GB. 공유 GPU 메모리(RAM 사용) RTX 3080 에서 14.3GB → B200 이면 거의 0 (추정)
      - 가중치 불러오기: 학습 프로세스 최대 약 24GB, 남은 RAM 0GB 까지 (측정, 팀 코드가 16.8GB 체크포인트를 통째로 읽음) → mmap 읽기로 줄일 수 있음 (추정, 모의 학습 사본에만 있음)
      - 학습 재료 대기열: 1장 약 8.5MB (정답 512×512×3 + 조건 512×512×4 + 옷 224×224×3, 계산) → 배치 256 이면 1묶음 약 2.2GB, 작업자 4명 × 2묶음이면 약 17GB (추정)
      - GPU 메모리를 넘기면 Windows 가 다시 RAM 을 빌림 (공유 한도 16,247MB) → 느려짐
      - B200 배치 확인 때 GPU 메모리와 RAM·공유 메모리를 함께 기록 (`기록\tools\monitor.py` 그대로 사용)
